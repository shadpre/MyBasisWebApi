## Existing transport baseline

Registration uses ApiUserDto and returns 200 with an empty body on success. Login uses LoginDto and returns UserId/Token/RefreshToken. Refresh accepts the AuthResponseDto shape and returns the same token-response fields. Keep or intentionally version/migrate these contracts; do not infer known downstream applications from the repository name.

Access-token generation currently uses HS256, configured issuer/audience and ExpiryMinutes, with sub=email and a separate uid claim. A stable user-ID subject is a possible improvement that needs compatibility treatment, not a claim about current behavior.
